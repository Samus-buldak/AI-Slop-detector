# Обновление сегментации и обучения

## Что изменено

- Rule-based сегментация остаётся автономной: отсутствие chat API не блокирует разбор письма и обучение `no_llm`.
- Для однострочного текста теперь выделяются очевидное приветствие и финальная подпись; промежуточный текст разбивается на фрагменты по предложениям и заголовкам для LLM-разметки. Исходные пробелы между фрагментами сохраняются при сборке зон.
- LLM-сегментатор использует общие настройки `API_TIMEOUT`, `SEM_BATCH` и `SEM_CONC`. При ошибке батча он делит его на меньшие запросы; для каждого письма остаётся строгая проверка индексов и границ.
- Обучение `no_llm` не требует chat API. Для LLM-разметки нужно явно включить `--llm-segmentation`; для отдельного дерева chat-оценок — `--with-llm`. Это независимые опции.
- При включённой LLM-сегментации обучение строго прекращается, если хотя бы одно письмо не размечено LLM: смешение LLM- и rule-based-разметки могло бы испортить распределение признаков.
- Исправлена дедупликация конфликтных меток, включая последовательности дубликатов `0/1/0`; вся конфликтная группа исключается.
- При анализе модель обязана совпадать с версией своего сегментатора: отдельно проверяется версия rule-based сегментации и отдельно — LLM prompt/model/endpoint. Старые несовместимые веса остаются загружаемыми, но дают `UNCERTAIN` до переобучения, чтобы не выдавать уверенный результат на изменившемся распределении признаков.
- Сохранение весов выполняется через staging-каталог с резервными копиями и откатом при ошибке публикации файлов.
- Все основные chat/vision-вызовы используют единый `API_TIMEOUT`.
- CLI заранее отклоняет противоречивую комбинацию `--no-semantic` с любым LLM-флагом и некорректные размеры обучающих выборок.
- Удалены две неиспользуемые старые реализации семантического анализа и связанный с ними локальный кэш. Они не участвовали в актуальном train/analyze-пайплайне; одна из реализаций ссылалась на уже отсутствующий `get_client()`.

## Команды обучения

Rule-based сегментация, без chat scoring:

```powershell
.\.venv-local\Scripts\python.exe -m src.api.local_qwen train
```

LLM-сегментация, но без chat scoring в дереве:

```powershell
.\.venv-local\Scripts\python.exe -m src.api.local_qwen train --llm-from-env --llm-segmentation
```

LLM-сегментация и отдельное дерево chat scoring:

```powershell
.\.venv-local\Scripts\python.exe -m src.api.local_qwen train --llm-from-env --with-llm --llm-segmentation
```

Для локальной chat-модели в LM Studio вместо `--llm-from-env` передай `--llm-model "точный-id-модели"`.

## О настройке «убрать беки»

В текущем проекте `backend: api` в `centroids.json` — это метка способа получения Qwen-эмбеддингов через OpenAI-compatible HTTP API, а не отдельный web/backend-сервис. Она нужна загрузчику для проверки модели. Основной API-клиент, LM Studio endpoint и необязательный FastAPI `/analyze` сохранены: удаление этих компонентов сломало бы обучение или интеграцию. Удалены только неиспользуемые дублирующие старые semantic-подсистемы.

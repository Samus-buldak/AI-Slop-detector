# Сегментация письма

## Что именно делится

Перед анализом письмо разбирается на четыре обязательные структурные зоны:

1. `subject` — тема из MIME-заголовка `Subject`;
2. `greeting` — начальное приветствие;
3. `body` — основное содержимое;
4. `signature` — заключительная формула, имя, должность и контактные данные.

Тема не генерируется и не угадывается моделью: она берётся из заголовка письма. При `no_llm` работают локальные правила: для многострочных писем анализируются физические строки, а для однострочного ввода дополнительно выделяются очевидное приветствие и финальная подпись. При `--llm-segmentation` используется line-ownership сегментация: chat-модель получает исходные строки либо (для однострочного ввода) индексируемые предложения/заголовки и определяет границу приветствия, границу подписи и явно распознаваемые цитаты старой переписки. Сами строки модель не переписывает. MIME-разбор, HTML-очистка и первичное удаление очевидной истории переписки выполняются локально.

## Как включить сегментацию именно нейросетью

Сегментация моделью включается флагом `--llm-segmentation`. Важно: `--with-llm` и `--llm-segmentation` — разные режимы:

- `--llm-segmentation` заставляет chat-модель размечать письмо на зоны при обучении и анализе;
- `--with-llm` добавляет отдельные оценки chat-модели в признаки второго дерева решений;
- можно включать оба флага вместе. Рекомендуемый режим проекта — оба флага.

Для Windows с локальной chat-моделью в LM Studio:

1. Загрузи в LM Studio две модели: Qwen3 Embedding 0.6B с ID `qwen3-embedding-local` и разговорную Qwen-модель.
2. Включи Local Server на порту `1234`.
3. Запусти `scripts/07_LOCAL_QWEN_TRAIN_WITH_LLM.bat`, введи точный ID разговорной модели. Скрипт запускает обучение с `--with-llm --llm-segmentation`.
4. При анализе используй тот же ID модели:

```powershell
.\.venv-local\Scripts\python.exe -m src.api.local_qwen analyze --llm-model "ТОЧНЫЙ_ID_CHAT_МОДЕЛИ" "letter.eml" --json
```

Если chat-модель берётся из исходного `.env`, используй `scripts/09_QWEN_ENV_LLM_TRAIN.bat` или команду:

```powershell
.\.venv-local\Scripts\python.exe -m src.api.local_qwen train --llm-from-env --with-llm --llm-segmentation
.\.venv-local\Scripts\python.exe -m src.api.local_qwen analyze --llm-from-env "letter.eml" --json
```

Внешнему провайдеру отправляются фрагменты письма. Не используй этот режим для конфиденциальной переписки без разрешения на такую передачу данных.

## Согласованность обучения и анализа

Если обучение запущено с `--llm-segmentation`, сегментация обязательна для каждого письма в `base`, `stack`, `calib` и `test`. При ошибке модели, невалидном JSON, превышении допустимой длины или fallback на эвристику обучение останавливается с ошибкой. Оно не смешивает нейросетевую и эвристическую разметку молча.

При последующем анализе проверяются совместимость chat-модели и endpoint с обучающей конфигурацией, а также версия промпта/алгоритма сегментации. Старые LLM-сегментированные веса автоматически не используют новую разметку: требуется переобучение. Если сегментация недоступна или конфигурация другая, результат переводится в `UNCERTAIN`, а в `warnings` указывается причина. Для модели, обученной без `--llm-segmentation`, остаётся детерминированная локальная сегментация правилами.

## Дополнительная структура

После четырёх зон строятся абзацы и предложения с точными смещениями. В расширенном режиме также формируются дополнительные аналитические части (вступление, основная часть, заключение, списки, постскриптум и смысловые блоки). Они используются как дополнительные признаки модели, когда обучение прошло с расширенной схемой.

В JSON-ответе `/analyze`:

- `segments` содержит текст и score по каждой из четырёх зон;
- `segmentation` содержит иерархию зон, абзацев и предложений;
- `segmentation.semantic_blocks` содержит смысловые блоки, если chat-модель вернула их;
- `segmentation_method` показывает фактический способ разметки (`llm_lines` или `rules`).

Смещения `start_offset` и `end_offset` измеряются в Python Unicode code points относительно текста в `segmentation.sources[zone]`, а не в байтах исходного `.eml`.

## Текстовые основания вердикта

В ответе есть два независимых набора пояснений:

- `textual_evidence` — точные совпадения с локальным словарём маркеров. Для каждого совпадения указываются зона, фраза, offsets, тип/сила и `used_by_tree`. Последнее поле показывает, участвовал ли соответствующий признак в реальном пути дерева решений.
- `llm_textual_evidence` — постфактум-пояснение chat-модели с цитатами. Каждая цитата проверяется программой на точное наличие в исходной зоне; выдуманные и перефразированные цитаты отбрасываются. Это пояснение не изменяет вердикт и не является внутренним объяснением эмбеддингов или дерева.

Приветствие, подпись, деловой стиль и отдельная шаблонная фраза сами по себе не доказывают ИИ-авторство. Система должна показывать основания и ограничения, а не выдавать вероятностный вывод за факт.

## Настройки запросов и поведение при ошибках

`API_TIMEOUT`, `API_RETRIES`, `SEM_BATCH` и `SEM_CONC` читаются из `.env` и применяются к chat-запросам. Значения ограничиваются допустимыми диапазонами, некорректная числовая настройка заменяется безопасным значением по умолчанию. При невалидном ответе или временной ошибке сегментатор делит большой батч на меньшие запросы; если один запрос всё равно не удался, для анализа возвращается rule-based результат с флагом `llm_used = false`. Обучение с `--llm-segmentation` такой fallback не принимает и прекращается, чтобы не смешивать разные способы сегментации.

Для одного длинного текстового поля фразы/предложения становятся отдельными индексируемыми элементами. Разделители между ними хранятся отдельно и возвращаются в результат без искусственной замены пробелов переносами строк.


## Совместимость артефактов

Правила сегментации версионируются отдельно от LLM-промпта. После изменения правил старые веса остаются доступными для диагностики, но анализ помечается `UNCERTAIN` до повторного обучения: иначе признаки, рассчитанные по новым границам зон, сравнивались бы с деревом, обученным на старых границах. Для LLM-схемы дополнительно проверяются ID chat-модели и endpoint.
